# Speaking Story Bank

This is the durable story inventory for the **People. Systems. Performance.** speaking platform.

The purpose is not to write finished talks here. The purpose is to preserve real experiences in a consistent format so they can be reused across keynotes, workshops, conference talks, LinkedIn posts, interviews, and future writing.

## Operating Rule

Capture the story **before** polishing it.

A useful story bank entry should preserve:
- what actually happened;
- why it mattered;
- what changed;
- what the story proves;
- where it can be used;
- which lines or images are worth keeping.

Do not force every story into a lesson. Some entries can remain "raw" until a pattern becomes clear.

## Story Status

Every story should use one of these statuses:

- **Raw** — captured but not interpreted yet.
- **Developing** — lesson or framing is emerging.
- **Talk Ready** — usable in a live talk with a clear setup, turn, and takeaway.
- **Signature** — unusually strong, memorable, and central to the platform.
- **Retired** — preserved, but no longer recommended for current use.

## Story Strength

Rate each story from 1–5 on:

- **Visual** — can the audience picture it?
- **Tension** — is there a problem, uncertainty, disagreement, or consequence?
- **Human** — does it reveal a person making a choice?
- **Transferable** — does the lesson apply beyond the original setting?
- **Proof** — does it demonstrate the platform idea rather than merely illustrate it?

A story does not need all 5s. The rating is only for finding the strongest material quickly.

## File Naming

Use:

`YYYY-MM-DD-short-story-name.md`

If the exact date is unknown, use:

`undated-short-story-name.md`

The date should reflect when the event happened if known, not when the file was written.

## Minimum Viable Capture

When a story occurs and there is no time to fully develop it, capture only:

1. **What happened**
2. **The moment that stuck**
3. **Why it might matter**
4. **Possible tags**

That is enough to preserve it for later development.

## Review Rhythm

Periodically review the bank and ask:

1. Which stories are becoming signature stories?
2. Which platform ideas lack proof stories?
3. Which stories are overused?
4. Which stories work for multiple audiences?
5. Which stories contain a stronger lesson than originally captured?
6. Which raw stories should be promoted to Developing or Talk Ready?
